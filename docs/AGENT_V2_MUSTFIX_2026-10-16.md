## P0 · 评估前提(不先做,后面全部免谈)

### M1.(必须)建立有功效的评估面,终结"5 个信息性对"时代
- **内容**:预注册 v1.3 全新盲测对集(规则迭代从未接触的暴露×结局对,来源库含客观测量),外加合成效应注入的端到端回归:在仿真队列中植入已知 OR(1.3/1.8/2.5)与零效应对照,跑全链,校验召回与假阳性控制。
- **证据**:E1 = R5.2 结论"性能上限受三重约束:规则冻结、gold 层功效、无规则独立依据";80 对中 5 信息性对,任何架构差异都测不出显著。
- **验收**:盲测集 ≥40 个可判对、预期信息性对 ≥15;合成回归以 CI 脚本形式可一键运行;此后**所有**框架改动的性能声明必须出自这两者之一。

## P1 · 知识层:静态规则 → 活证据

### M2.(必须)规则状态机 + 持续证据监视
- **内容**:每条规则增加生命周期状态 `active / disputed / deprecated`;新增文献扫描调度器(复用 fetch_pubmed + literature_validation 的两步判定协议),按预注册阈值自动迁移状态(如方向投票连续两轮 flip → disputed);disputed 规则报告自动降权并进人工裁决队列。
- **证据**:E2 = 规则库 2026-10 冻结后即与文献脱钩;文献层判定协议经三轮演进已收敛(round3+round4 为准)。
- **验收**:给定增量文献输入,状态迁移可复现(同输入同输出);r08 类 mixed 规则能稳定落在 disputed;人工裁决有审计日志。

### M3.(必须)证据池逐条溯源可复现
- **内容**:每个 chunk 的 provenance 必须含完整检索式、数据库、日期、参数版本,使 evidence_chunks.jsonl 可审计重建;当前"多轮抓取+人工清洗不可重建"的状态不允许延续到 V2。
- **验收**:对任一 chunk,能从 provenance 字段重放检索并命中同源记录;校验器(build_evidence_base.py E3)对 provenance 结构 fail-loud。

## P2 · 任务层:升维

### M4.(必须)砍掉 pair 级 YES/NO 作为主任务
- **内容**:主任务改为**个体级筛查报告**(输入:个人暴露谱+年龄性别;输出:转诊优先级、命中规则及其证据等级、不确定性说明)或**自动分析员**(假设→预注册→本地确证→报告)。pair 级评测降级为回归测试,不再是产品形态。
- **证据**:E3 = pair 级关联判定无临床部署价值,且其 gold 由同义反复对主导(复证集中于血糖×糖尿病眼病,定义包含关系)。
- **验收**:demo 输入一份个体档案,产出带规则引用与证据等级的结构化报告;报告里每个结论可回溯到 chunk 级出处(现有 report.py 的溯源链保留)。

### M5.(必须)输出必须携带测量适用性声明
- **内容**:任何判定的输出必须附"该结论依赖的结局测量方式(自报/检查/影像)+ 在该测量下的可信度档位";测量不支持时**拒绝回答**,禁止用代理变量硬答。
- **证据**:E4 = 八队列研究核心发现:自报白内障测"被诊断过",同名义结局跨人群不是同一构念(NHANES 自报 OR 4.27 vs 客观 1.32);KNHANES 曾用酒驾变量产出假信号进金标准。
- **验收**:构造"自报结局数据集"用例,agent 对检查类规则(如 r16 IOP 类)返回 refuse-with-reason 而非 YES/NO。

## P3 · 测量感知转运(差异化能力)

### M6.(必须)dataset instrument profile 机制
- **内容**:每个目标数据集建 profile(结局测量方式、参考患病率、可判暴露清单、设计变量有无),规则应用前先过 profile 门;现有 entities_b 的 `*_judgeable` 布尔列是其雏形,扩展为 per-dataset 结构化 profile。
- **验收**:profile 门对 8 个老龄队列预测可测 cell,与实际 18/168 可测性对照,给出 AUC——这本身是可发表的评估。

### M7.(必须)reference-prevalence gate 代码化
- **内容**:变量操作化后,患病率与官方/文献参考值偏离 >2.5× 时 fail-loud(现在只是 R11 稿件里的方法学描述,必须变成运行时守卫)。
- **证据**:E5 = 该 gate 曾在稿件中拦截操作化错误;KNHANES 吸烟 1.7%、饮酒 3.8% 这类荒谬暴露率本应被它拦下。
- **验收**:注入故意错误的操作化(如把酒驾当饮酒),gate 必须报警并阻断该暴露进入分析。

## P4 · 推理层:冻结与删除

### M8.(禁止)继续投入检索/embedding/prompt/仲裁增强
- **内容**:G2 定格为默认管线;G3/G4/G5 代码路径归档或删除(负结果保留在文档);V2 的一切性能改进声明必须来自 M1 评估面,禁止再用旧 80 对 gold 报"提升"。
- **证据**:E6 = G2 vs G0 p=0.50;G3 no-op;G4 有害(0.500→0.417);G5a 无增益、G5b 零触发;"检索层不是瓶颈"。

### M9.(必须)仲裁器的诚实降级
- **内容**:要么给仲裁器可测量的否决行为(在 M1 评估面上证明否决带来显著增益),要么在所有对外输出中显式标注"仲裁器为透传,未行使否决"。
- **证据**:E7 = 仲裁 3 次全 YES,从未否决;limitations 已写"不得归因 LLM 把关"。

## P5 · 工程纪律(两次踩坑的教训,必须制度化)

### M10.(必须)全链一键化 + CI 回归
- **内容**:run_all.py 式 canonical 链(已存在)+ M1 合成回归进 CI;单脚本破坏 headline 的静默回退类问题(evaluate.py 单跑回退 freq 口径)必须加守卫。
- **验收**:CI 在无 LLM 服务时仍可跑纯本地子集;任何一步 fail-loud。

### M11.(必须)预测记录加代际(epoch)字段
- **内容**:所有 jsonl 追加写必须带 `epoch`/`generation` 字段,summary 按"最新完整 epoch"取数,杜绝代际混叠(R4、R11 两次发生)。
- **验收**:故意写入半截 run 后,summary 正确忽略并告警。

### M12.(必须)变量操作化字典成为唯一事实源
- **内容**:evaluate*.py 内散落的变量名/切点/参照组定义全部迁入 configs/variable_map.yaml(17 处更正的延续),代码只读字典;E:\ 路径进配置。
- **证据**:E8 = A1–A4 变量错误的根因即操作化散落代码且无字典校验。
- **验收**:改字典不改代码,操作化生效;字典带 schema 校验。
