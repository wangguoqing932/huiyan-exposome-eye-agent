# R25 叙事重构（2026-10-23）

## 触发

作者明确要求：论文不能只落在“智能体验证应报告规则层面可转运性”这一句；叙事顺序必须是

1. 智能体很强、优于普通大模型；
2. 在多个数据集上都优于基线；
3. 可以给人使用（有界面、有可追溯报告）；
4. 最后才发现：agent 验证应报告规则层面可转运性，而不仅是聚合系统性能。

## 改动

### 标题

`An explainable rule-knowledge-graph-LLM agent for exposome-eye screening: strong system performance and usable reports, but poor rule transportability across eight cohorts`

原标题只写“strong system performance but poor rule transportability”，未体现“可用报告”；新标题保留强/弱对照，同时把 usable reports 写进主标题。

### 摘要（406 词，单页排下）

- Background 改为 agent-first，不再先讲规则来源。
- Methods 五个验证目标重排：系统分类 → 工作界面与规则/来源可追溯 → 八队列可转运性 → 规则方向 → 四库文献一致性；四个 independence tiers 保留。
- Results 先报系统性能：NHANES qwen 代 0.522 vs 0.392/0.335/0.080；zhipu 代 0.480 vs 0.186/0.178/0.069；KNHANES 301 对 0.360 vs 0.145/0.135/0.094，McNemar 全显著。之后才写 positive control、规则方向、文献一致性、traceability。
- Conclusions 先写“strong and usable”，再写规则不转运与 measurement 约束，最后落在“Agent validation should therefore report rule-level transportability, not only aggregate performance”。

### Results

在 `## System performance` 末新增 KNHANES 301 对段落（full 0.360 > LightRAG 0.145 > pure LLM 0.135 > naive RAG 0.094，McNemar 全显著），并写明 agent 返回 clinician card / patient handout / research table / policy brief，且有 Streamlit 界面。这样“多个数据集”与“可以给人使用”都有正文证据，而不是只靠摘要声称。

### Discussion

`## Principal findings` 三条改为：

1. **the agent is strong and usable**：NHANES 双代 + KNHANES 均优于三条基线；返回 source-linked clinician report，Streamlit 界面；性能附着在可用产物上。
2. **aggregate performance does not establish that its rules transport**：6/21 testable；18 对中 8 复证 / 8 无信息 / 2 反证；两条过预注册标准但 PI 跨 null；positive control 失败；原因是 measurement。
3. **agent validation should report rule-level transportability, not only aggregate system performance**：强、可用、优于普通 LLM 与规则失败可以同时成立。

`## Limitations` 新增 usability 段：有可运行界面与可审计报告，不等于临床医生认为可用或能改善决策；未做可用性试验、未临床部署。

### Conclusion

先写 agent 在 NHANES 双代与独立 KNHANES 上优于 LLM/RAG 基线、返回可溯报告；再写规则不转运；最后写“The lesson is not that the agent is weak… Agent validation should therefore report rule-level transportability alongside aggregate system performance”。
